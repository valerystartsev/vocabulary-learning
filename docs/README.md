# Документация проекта Adaptation — указатель по гайдам

Этот файл — отправная точка для любого, кто работает с проектом. В папке `docs/` лежит несколько документов разного назначения. Здесь описано, какой из них открывать в каждой конкретной ситуации, в каком порядке читать, и что делать, если что-то пошло не так.

Если вы открыли этот документ впервые, прочитайте раздел 1, а потом возвращайтесь к указателю по мере необходимости.

---

## 1. Кто и что должен прочитать

Найдите свою роль ниже и переходите к указанным документам.

### 1.1. Преподаватель, который впервые получил доступ к системе

Цель: войти в Teacher Dashboard и увидеть прогресс студентов.

Порядок действий:

1. Прочитайте раздел 2 (краткий обзор проекта) этого файла.
2. Откройте `supabase-setup-guide.md`, выполните разделы 2 и 9. Этого достаточно, чтобы войти в систему и попасть в Teacher Dashboard.
3. Если что-то не работает (студентов нет, прогресс не виден) — раздел 11 в `supabase-setup-guide.md`.

Все остальные документы преподавателю смотреть не обязательно. Они нужны разработчику и администратору базы данных.

### 1.2. Администратор базы данных, который разворачивает систему с нуля

Цель: настроить новый проект Supabase для приложения Adaptation.

Порядок действий:

1. Откройте `supabase-setup-guide.md` и прочитайте его полностью, по порядку.
2. Откройте `supabase-init.sql`, скопируйте всё содержимое и выполните в SQL Editor Supabase. Это создаст таблицу, триггер, политики и подтянет метаданные.
3. Вернитесь к `supabase-setup-guide.md` и выполните разделы 7 (URL Configuration) и 8 (Secure email change) — эти настройки делаются в UI и в скрипт не входят.
4. Пройдите чек-листом в разделе 13.

После этого система готова к работе.

### 1.3. Разработчик, который правит контент курса (тексты, видео, упражнения)

Цель: изменить контент юнита, заменить видео, добавить упражнение.

Порядок действий:

1. Откройте `content-editing-guide.md` и найдите нужный раздел.
2. Внесите правку в соответствующий файл в `src/data/`.
3. Зафиксируйте изменения в git и отправьте в репозиторий. Vercel автоматически пересоберёт прод за одну-две минуты.

### 1.4. Разработчик, который занимается технической эксплуатацией

Цель: понять архитектуру, найти конкретный механизм или баг.

Документы по нарастанию глубины:

1. `audit-report.md` — аудит архитектуры перед мерджем Units 3 и 4. Что и почему было устроено именно так.
2. `final-integration-report.md` — итоговый отчёт об интеграции перед запуском.
3. `refactoring-plan.md` — план последовательного рефакторинга (R1–R6).
4. `interactive-lab-plan.md` — план разработки раздела Interactive Lab.
5. `supabase-setup-guide.md` — описание архитектуры данных (раздел 3) и схемы базы (раздел 4).

### 1.5. Тот, кто составляет отчёт об изменениях

Используйте готовый файл `adaptation-changes-report.docx` — он содержит 24 пронумерованных изменения с подробным описанием. Документ создан как формальный отчёт, без эмодзи и без упоминания каких-либо автоматизированных инструментов.

## 2. Краткий обзор проекта

Этот раздел поможет понять, что такое Adaptation и из чего он состоит. Полезен на старте.

### 2.1. Что это

Adaptation — это онлайн-курс делового английского языка для студентов уровня A1–A2. Содержит четыре тематических юнита:

- Unit 1 — Markets and Monopolies (рынки и конкуренция).
- Unit 2 — Growth and Labour (экономический рост и труд).
- Unit 3 — Money and Banking (деньги и банки).
- Unit 4 — Measuring the Economy (макроэкономические показатели).

Дополнительно в курс встроен раздел Interactive Lab — набор из семи интерактивных инструментов (симулятор кредита, балансовый отчёт, калькулятор ВВП и так далее), доступных как сами по себе, так и из соответствующих юнитов.

### 2.2. Адрес

Продуктивный домен: `https://adaptation-fa.online` (либо `https://adaptation-fa.ru` в зависимости от того, какой из них активен). Оба варианта ведут на одно и то же приложение.

### 2.3. Стек технологий

- Клиент: React 18 + Vite.
- Бекенд: Supabase (PostgreSQL для данных, Supabase Auth для аутентификации).
- Хостинг: Vercel с автоматической сборкой из ветки `main`.
- Управление кодом: GitLab.

### 2.4. Роли пользователей

- Студент — обычный зарегистрированный пользователь. Видит свой профиль, проходит курс, видит свой прогресс.
- Студент-ФинУна — обычный студент с дополнительным флагом `university_tracking = true`. Попадает в Teacher Dashboard.
- Преподаватель — пользователь с адресом `emzakhtser@mail.ru`. Видит список студентов-ФинУна и их прогресс.

Дополнительных ролей в системе нет.

## 3. Описание каждого файла в `docs/`

### 3.1. README.md (этот файл)

Указатель по гайдам. Кто что должен прочитать, где какая информация.

### 3.2. supabase-setup-guide.md

Полное руководство по настройке Supabase. 13 разделов. Главный документ для администратора базы данных и преподавателя.

Открывать когда:

- Разворачивается новый проект.
- Не виден список студентов в Teacher Dashboard.
- Не работает восстановление пароля.
- Не работает смена email.
- Нужно проверить, что политики Row-Level Security настроены правильно.

### 3.3. supabase-init.sql

Готовый SQL-скрипт, который разворачивает всё необходимое в базе данных за один запуск. Идемпотентный: повторное выполнение не сломает существующие объекты.

Открывать когда:

- Разворачивается новый проект Supabase с нуля.
- Сбита часть объектов (триггер, политики), нужно восстановить.

Не подходит для частичных правок — выполняется целиком.

### 3.4. supabase-full-reference.md

Историческая полная справка по базе данных. В ней есть всё то же, что и в `supabase-setup-guide.md`, плюс расширенные пояснения по архитектуре. Менее структурирована, но полезна для глубокого погружения.

Открывать когда:

- `supabase-setup-guide.md` не закрывает редкий вопрос.
- Нужны дополнительные подробности по форматам JSONB-данных.

### 3.5. supabase-setup.sql

Старая версия SQL-инициализатора. Оставлена для совместимости.

Использовать `supabase-init.sql` вместо неё.

### 3.6. content-editing-guide.md

Руководство по редактированию контента курса. Описывает, как менять тексты, видео, упражнения, словарь, итоговые тесты и интерактивные виджеты.

Открывать когда:

- Нужно изменить любой текст внутри юнита.
- Нужно заменить видео в Media Lab.
- Нужно добавить или изменить упражнение.
- Нужно добавить новый юнит или новую секцию.

### 3.7. audit-report.md

Аудит архитектуры курса перед мерджем Units 3 и 4. Содержит таблицу проблем и принятых решений.

Открывать когда:

- Нужно понять, почему какой-то механизм работает именно так.
- Готовится новая большая фича — посмотреть, какие архитектурные решения уже приняты.

### 3.8. final-integration-report.md

Итоговый отчёт об интеграции перед запуском. Двенадцать чек-пойнтов, по которым проверена готовность.

Открывать когда:

- Готовится новый запуск, нужно вспомнить структуру проверки.

### 3.9. refactoring-plan.md

Поэтапный план рефакторинга курса (этапы R1–R6). Большая часть уже выполнена.

Открывать когда:

- Нужно понять, что и в каком порядке менялось.

### 3.10. interactive-lab-plan.md

План разработки раздела Interactive Lab (четыре фазы).

Открывать когда:

- Нужно понять структуру Interactive Lab.
- Планируется добавление нового инструмента.

### 3.11. units-3-4-concept.html

Концепт Units 3 и 4 в формате HTML. Можно открыть в браузере для просмотра.

Открывать когда:

- Нужно посмотреть исходное видение Units 3 и 4.

### 3.12. teacher-dashboard-mockup.html и teacher-dashboard.png

Графические мокапы Teacher Dashboard. HTML открывается в браузере, PNG — обычная картинка.

Открывать когда:

- Хочется показать преподавателю заранее, как будет выглядеть его панель.
- Нужно дать дизайнерскую правку.

### 3.13. adaptation-changes-report.docx

Формальный отчёт о 24 изменениях в курсе. Word-документ, готовый к печати.

Открывать когда:

- Преподаватель попросил отчёт о проделанной работе.
- Готовится презентация для администрации факультета.

## 4. Сценарии «у меня не работает»

Эти сценарии чаще всего встречаются. Указано, какой документ открывать.

### 4.1. Я преподаватель, в Teacher Dashboard пусто

Откройте `supabase-setup-guide.md`, раздел 11.1.

### 4.2. У всех студентов прогресс 0%, но они работают

Откройте `supabase-setup-guide.md`, раздел 11.2.

### 4.3. Студент написал, что не приходит письмо для восстановления пароля

Откройте `supabase-setup-guide.md`, раздел 7 (URL Configuration). Проверьте Redirect URLs.

### 4.4. Студент поставил галочку «ФинУна», но в дашборде его нет

Откройте `supabase-setup-guide.md`, раздел 11.3.

### 4.5. Хочу заменить видео в Media Lab Unit 3

Откройте `content-editing-guide.md`, раздел про Media Lab.

### 4.6. Хочу добавить новое упражнение в Unit 2

Откройте `content-editing-guide.md`, раздел про упражнения.

### 4.7. Хочу сделать конкретного студента отслеживаемым

Откройте `supabase-setup-guide.md`, раздел 12.1.

### 4.8. Сайт не открывается совсем

Это проблема не Supabase, а инфраструктуры. Проверьте статус Vercel:
- Зайдите в `https://vercel.com`, откройте проект, посмотрите вкладку Deployments.
- Если последний деплой завершился ошибкой — откройте его логи.

### 4.9. Студент жалуется на конкретную ошибку

Попросите его прислать снимок экрана с ошибкой. Если ошибка связана с авторизацией — раздел 11 в `supabase-setup-guide.md`. Если с контентом — `content-editing-guide.md` (возможно, ошибка в данных юнита).

## 5. Порядок действий при первом запуске системы

Если вы разворачиваете систему «с нуля», выполняйте шаги строго по порядку.

1. Создайте проект в Supabase (`https://supabase.com`, кнопка New Project).
2. Откройте `supabase-init.sql`, скопируйте всё содержимое, вставьте в SQL Editor проекта, выполните.
3. Откройте `supabase-setup-guide.md`, раздел 7. Заполните Site URL и Redirect URLs.
4. Раздел 8 того же файла. Включите Secure email change.
5. Раздел 9 того же файла. Зарегистрируйте преподавательскую учётную запись на `emzakhtser@mail.ru` и подтвердите email.
6. Войдите на сайт под этой учётной записью. Должно произойти автоматическое перенаправление на `/teacher`.
7. Пройдитесь по чек-листу в разделе 13.

После этого можно открывать регистрацию для студентов.

## 6. Где брать помощь

- По всем вопросам, связанным с Supabase, обращайтесь к `supabase-setup-guide.md`, раздел 11 (типовые проблемы) и раздел 12 (массовые операции).
- По всем вопросам, связанным с контентом, обращайтесь к `content-editing-guide.md`.
- По всем вопросам, связанным с архитектурой, начните с `audit-report.md` и `refactoring-plan.md`.

Если ни один документ не отвечает на ваш вопрос, опишите проблему максимально подробно с указанием:

- Что вы делаете (шаги).
- Что ожидаете увидеть.
- Что видите на самом деле.
- Снимок экрана с ошибкой.

С этими данными можно быстро определить, в какой части системы проблема.
